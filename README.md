# Task Manager — Full Stack Application

## Опис проєкту

**Task Manager** — вебзастосунок для керування проєктами та завданнями.

Проєкт складається із серверної частини (REST API) та клієнтської частини (React-застосунок), які взаємодіють між собою через HTTP-запити та Socket.IO.

Backend забезпечує реєстрацію й авторизацію користувачів, розмежування прав доступу, управління проєктами, завданнями, коментарями, файлами та сповіщеннями.

Frontend реалізований на React і TypeScript та забезпечує користувацький інтерфейс для взаємодії із серверною частиною.

## Встановлення та запуск

### Вимоги

- Node.js 24 LTS

- npm

- PostgreSQL

### 1. Клонування репозиторію

```bash

git clone https://github.com/EvilDahaka/Lab1-6-Web.git

cd Lab1-6-Web

```

### 2. Встановлення залежностей Backend

У кореневій папці проєкту виконати:

```bash

npm install

```

### 3. Налаштування змінних середовища Backend

Створити файл `.env` у корені проєкту:

```env

DATABASE_URL="postgresql://USER:PASSWORD@localhost:5432/task_manager?schema=public"

JWT_SECRET="your_long_random_secret"

PORT=3000

CLIENT_URL="http://localhost:5173"

```

Замість `USER` і `PASSWORD` указати власні облікові дані PostgreSQL. Для `JWT_SECRET` використати довгий випадковий секрет.

`CLIENT_URL` задає адресу клієнтського застосунку.

**Не публікувати файл `.env` і не додавати його до Git.**

### 4. Підготовка бази даних

Переконатися, що PostgreSQL запущений, а база даних `task_manager` створена.

Застосувати наявні міграції:

```bash

npx prisma migrate deploy

```

Згенерувати Prisma Client:

```bash

npx prisma generate

```

Для створення нової міграції після зміни `prisma/schema.prisma` використати:

```bash

npx prisma migrate dev --name migration_name

```

### 5. Запуск Backend

Режим розробки:

```bash

npm run dev

```

Звичайний запуск:

```bash

npm start

```

За замовчуванням сервер працює на порту `3000`, якщо інший порт не заданий через `PORT`.

### 6. Встановлення залежностей Frontend

Перейти до каталогу клієнтської частини:

```bash

cd client

npm install

```

### 7. Налаштування змінних середовища Frontend

Для локальної розробки використовується файл `.env.development`:

```env

VITE_API_URL=http://localhost:3000/api
VITE_SOCKET_URL=http://localhost:3000

```

Для production-середовища використовується файл `.env.production`:

```env

VITE_API_URL=https://task-manager-api-production-154a.up.railway.app/api
VITE_SOCKET_URL=https://task-manager-api-production-154a.up.railway.app

```

Ці файли містять адресу API для відповідного середовища. Секретні ключі та паролі у frontend-змінних зберігати не можна.

### 8. Запуск Frontend

Для запуску в режимі розробки:

```bash

npm run dev

```

Після запуску застосунок буде доступний за адресою:

```text

http://localhost:5173/

```

### 9. Перевірка та збірка Frontend

Перевірка коду за допомогою ESLint:

```bash

npm run lint

```

Форматування коду:

```bash

npm run format

```

Збірка для production:

```bash

npm run build

```

Попередній перегляд production-збірки:

```bash

npm run preview

```

**TanStack React Query** використовується для отримання, кешування та оновлення даних із сервера.

**React Hook Form та Zod** використовуються для роботи з формами та перевірки введених даних.

**React Hot Toast** використовується для відображення повідомлень про результати операцій.

## Основні маршрути API

Наведені нижче маршрути описують основні можливості API. Детальні параметри запитів і схеми відповідей наведені у Swagger.

### Авторизація — `/api/auth`

- `POST /api/auth/register` — реєстрація користувача.

- `POST /api/auth/login` — вхід у систему.

- `POST /api/auth/refresh` — оновлення токенів.

- `POST /api/auth/logout` — вихід із системи та відкликання refresh-токена.

- `POST /api/auth/change-password` — зміна пароля.

- `GET /api/auth/me` — отримання даних поточного користувача.

### Користувачі — `/api/users`

- `GET /api/users` — отримання списку користувачів.

- `GET /api/users/:id` — отримання користувача за ID.

- `POST /api/users` — створення користувача.

- `PUT /api/users/:id` — оновлення даних користувача.

- `DELETE /api/users/:id` — видалення користувача.

### Проєкти — `/api/projects`

- `GET /api/projects` — отримання списку проєктів.

- `GET /api/projects/:id` — отримання проєкту за ID.

- `POST /api/projects` — створення проєкту.

- `PUT /api/projects/:id` — оновлення проєкту.

- `DELETE /api/projects/:id` — видалення проєкту.

### Завдання — `/api/tasks`

- `GET /api/tasks` — отримання списку завдань.

- `GET /api/tasks/:id` — отримання завдання за ID.

- `POST /api/tasks` — створення завдання.

- `PUT /api/tasks/:id` — оновлення завдання.

- `DELETE /api/tasks/:id` — видалення завдання.

Для списку завдань передбачені параметри пошуку, фільтрації та пагінації, зокрема `page`, `limit`, `search`, `status`, `priority` і `projectId`.

### Коментарі — `/api/comments`

- `GET /api/comments` — отримання доступних користувачу коментарів.

- `GET /api/comments/:id` — отримання коментаря за ID.

- `POST /api/comments` — створення коментаря до завдання.

- `PUT /api/comments/:id` — оновлення коментаря.

- `DELETE /api/comments/:id` — видалення коментаря.

### Файли — `/api/files`

- `GET /api/files` — отримання списку доступних файлів.

- `GET /api/files/:id` — отримання інформації про файл.

- `POST /api/files` — завантаження файлу.

- `PUT /api/files/:id` — заміна файлу.

- `DELETE /api/files/:id` — видалення файлу.

Для завантаження файлу використовується формат `multipart/form-data` з полем `file`.

### Сповіщення — `/api/notifications`

- `GET /api/notifications` — отримання власних сповіщень.

- `GET /api/notifications?page=1&limit=20` — отримання сповіщень із пагінацією.

Маршрути сповіщень захищені автентифікацією. Користувач може переглядати й змінювати лише власні сповіщення.

## Взаємодія в реальному часі — Socket.IO

Socket.IO забезпечує обмін подіями між сервером і підключеними клієнтами без необхідності постійно надсилати HTTP-запити для отримання оновлень.

### Автентифікація

Під час встановлення Socket.IO-з'єднання клієнт передає JWT у параметрі `auth.token`. Сервер перевіряє токен перед установленням з'єднання.

Приклад підключення клієнта:

```javascript

import { io } from "socket.io-client";

const socket = io("http://localhost:3000", {

  auth: {

    token: accessToken

  }

});

```

Для цього прикладу клієнтський проєкт має містити пакет `socket.io-client`.

Для розгорнутого сервера замість локальної адреси використовується:

```javascript

const socket = io(

  "https://task-manager-api-production-154a.up.railway.app",

  {

    auth: {

      token: accessToken

    }

  }

);

```

### Події присутності користувачів

| Подія | Напрямок | Призначення |

|---|---|---|

| `connected` | Сервер → клієнт | Підтвердження встановлення з'єднання |

| `presence:list` | Сервер → клієнт | Поточний список користувачів онлайн |

| `presence:get` | Клієнт → сервер | Запит актуального списку користувачів онлайн |

| `presence:update` | Сервер → клієнти | Повідомлення про появу користувача онлайн або його відключення |

### Події проєктів, завдань і коментарів

- `project:created` — створено проєкт.

- `project:updated` — оновлено проєкт.

- `project:deleted` — видалено проєкт.

- `task:created` — створено завдання.

- `task:updated` — оновлено завдання.

- `task:deleted` — видалено завдання.

- `comment:created` — створено коментар.

- `comment:updated` — оновлено коментар.

- `comment:deleted` — видалено коментар.

- `notification` — отримано персональне сповіщення.

- `socket:error` — повідомлення про помилку Socket.IO.

### Кімнати проєктів

Кімнати Socket.IO використовуються для організації обміну подіями в межах конкретного проєкту.

| Подія | Напрямок | Призначення |

|---|---|---|

| `room:join` | Клієнт → сервер | Запит на приєднання до кімнати проєкту |

| `room:joined` | Сервер → клієнт | Підтвердження приєднання |

| `room:leave` | Клієнт → сервер | Запит на вихід із кімнати проєкту |

| `room:left` | Сервер → клієнт | Підтвердження виходу з кімнати |

| `socket:error` | Сервер → клієнт | Повідомлення про помилку або відсутність доступу |

Назва кімнати формується за шаблоном `project:{projectId}`, наприклад `project:12`.

Приклад приєднання до кімнати:

```javascript

socket.emit("room:join", 12);

socket.on("room:joined", (data) => {

  console.log("Приєднано до проєкту:", data.projectId);

});

socket.on("socket:error", (error) => {

  console.error(error.message);

});

```

Сервер перевіряє коректність ID та доступ користувача до проєкту. У поточній реалізації приєднання дозволяється власнику проєкту або користувачу, призначеному виконавцем хоча б одного завдання цього проєкту.

Вихід із кімнати:

```javascript

socket.emit("room:leave", 12);

socket.on("room:left", (data) => {

  console.log("Вихід із кімнати проєкту:", data.projectId);

});

```

### Збереження сповіщень та онлайн-статуси

Сповіщення зберігаються в PostgreSQL за допомогою Prisma. Це дає змогу переглядати їх через REST API навіть після повторного підключення користувача.

Онлайн-статуси в поточній реалізації зберігаються в пам'яті сервера. Тому після перезапуску сервера список активних користувачів формується заново.

Socket.IO підключено до React-клієнта. Після авторизації клієнт встановлює з'єднання із сервером, отримує персональні сповіщення та оновлення онлайн-статусів. У межах лабораторної роботи № 06 реалізовано базові сценарії першого рівня. Частина інших можливостей frontend ще потребує доопрацювання та додаткового тестування.

| Запит | HTTP-статус | Результат |

|---|---:|---|
