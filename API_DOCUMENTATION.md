# Task Manager API Documentation

## 1. Загальна інформація

**Назва проєкту:** Task Manager API

**Опис:** REST API для керування користувачами, проєктами, завданнями та коментарями.

**Base URL:**
```text
http://localhost:3000
```

**Використані технології:**
- Node.js
- Express.js
- PostgreSQL
- Prisma ORM
- Zod для валідації даних

Для передавання даних використовується формат JSON.

## 3. Перевірка доступності сервера

### GET `/api/health`

Перевіряє, чи працює сервер.

**Приклад відповіді:**
```json
{
  "status": "ok"
}
```

## 4. Користувачі (Users)

### Створення користувача

**POST** `/api/users`

Тіло запиту:
```json
{
  "name": "Test User",
  "email": "test@example.com"
}
```

**Приклад відповіді:**
```json
{
  "id": 1,
  "name": "Test User",
  "email": "test@example.com",
  "createdAt": "2026-10-19T12:50:59.263Z"
}
```

### Отримання списку користувачів

**GET** `/api/users`

Повертає список зареєстрованих користувачів.

### Отримання користувача за ID

**GET** `/api/users/:id`

Приклад: `/api/users/1`

### Оновлення користувача

**PUT** `/api/users/:id`

Приклад тіла запиту:
```json
{
  "name": "Updated User"
}
```

### Видалення користувача

**DELETE** `/api/users/:id`

Видаляє користувача із зазначеним ідентифікатором, якщо це дозволяють пов'язані записи бази даних.

## 5. Проєкти (Projects)

### Створення проєкту

**POST** `/api/projects`

Тіло запиту:
```json
{
  "name": "Test Project",
  "description": "Test project for API",
  "ownerId": 1
}
```

Поле `ownerId` містить ідентифікатор користувача — власника проєкту.

### Отримання списку проєктів

**GET** `/api/projects`

Повертає список проєктів із пов'язаною інформацією про власника та завдання.

### Отримання проєкту за ID

**GET** `/api/projects/:id`

Приклад: `/api/projects/1`

### Оновлення проєкту

**PUT** `/api/projects/:id`

Приклад тіла запиту:
```json
{
  "name": "Updated Project",
  "description": "Updated project description"
}
```

### Видалення проєкту

**DELETE** `/api/projects/:id`

Видаляє проєкт за ідентифікатором, якщо це дозволяють пов'язані записи.

## 6. Завдання (Tasks)

### Створення завдання

**POST** `/api/tasks`

Тіло запиту:
```json
{
  "title": "Test Task",
  "description": "Test task for API",
  "projectId": 1,
  "assigneeId": 1
}
```

`projectId` визначає проєкт, до якого належить завдання. `assigneeId` визначає користувача, якому призначено завдання.

### Отримання списку завдань

**GET** `/api/tasks`

Повертає список завдань із пов'язаними проєктами, виконавцями та коментарями.

### Отримання завдання за ID

**GET** `/api/tasks/:id`

Приклад: `/api/tasks/1`

### Оновлення завдання

**PUT** `/api/tasks/:id`

Приклад тіла запиту:
```json
{
  "status": "IN_PROGRESS"
}
```

Можливі статуси:
- `TODO` — завдання ще не розпочато;
- `IN_PROGRESS` — завдання виконується;
- `DONE` — завдання завершено.

Можливі пріоритети: `LOW`, `MEDIUM`, `HIGH`.

### Видалення завдання

**DELETE** `/api/tasks/:id`

Видаляє завдання за ідентифікатором, якщо це дозволяють пов'язані записи.

## 8. Формат запитів

Для запитів, які передають дані, використовується заголовок:

```text
Content-Type: application/json
```

Ідентифікатор `:id` у URL потрібно замінювати на фактичний ID запису, наприклад `/api/users/1`.

## 9. Обробка помилок

API може повертати такі HTTP-статуси:

- **200 OK** — запит виконано успішно;
- **201 Created** — запис створено, якщо маршрут використовує цей статус;
- **400 Bad Request** — некоректні дані запиту;
- **404 Not Found** — запис або маршрут не знайдено;
- **500 Internal Server Error** — внутрішня помилка сервера.

Приклад помилки:
```json
{
  "error": "Маршрут не знайдено"
}
```

## 10. Запуск проєкту

Встановити залежності:

```bash
npm install
```

Застосувати міграції бази даних:

```bash
npx prisma migrate dev
```

Запустити сервер у режимі розробки:

```bash
npm run dev
```

Перевірити доступність API:

```text
GET http://localhost:3000/api/health
```

Очікувана відповідь:

```json
{
  "status": "ok"
}
```
